# XIAO ESP32C6 + STCC4（CO2・温湿度）→ ダッシュボード

DFRobot Gravity STCC4（SEN0678）で測った CO2・温度・湿度を、Pico W と同じ方法で
Firestore の `environmental_data` に2分ごとに送る。CO2 は `co2`（ppm、整数）として送り、
ハウスカード・7インチ画面・ハウス詳細に表示される（CO2 を送っているハウスだけ）。

## 配線

| STCC4（Gravity） | XIAO ESP32C6 |
|---|---|
| VCC（+） | 3V3 |
| GND（−） | GND |
| SDA（D） | D4 |
| SCL（C） | D5 |

I2C アドレスは `0x64`。温湿度は STCC4 に内蔵の SHT41 で測る。

## 初回だけの準備（Firebase 側）

1. **Firestore のルールを貼り直す**：`firestore.rules` を Firebase コンソール →「Firestore Database」→「ルール」に
   **1行目の `rules_version = '2';` から最後まで全部**貼り付けて「公開」（CO2 を送れるようにする変更が入っている。
   貼り直さないと `送信拒否(403)` になる）
2. センサー用アカウント（`sensor@farm-dashboard.local`）は Pico W と同じものを使う（新しく作らなくてよい）
3. `secrets.h` の `LOCATION` に書くハウスが、ダッシュボードの「温室ハウス一覧」に登録されていること

## 書き込み（Arduino IDE）

1. ボード「esp32 by Espressif Systems」（3.x）、ライブラリ「DFRobot_STCC4」を入れておく
2. `stcc4_firestore` フォルダを開き、`secrets_example.h` をコピーして同じフォルダに `secrets.h` を作り、
   Wi-Fi・センサー用アカウントのパスワード・`LOCATION` を書く（**`secrets.h` は Git に入れない**）
3. ボード **XIAO_ESP32C6** を選んで書き込む
4. シリアルモニタ（115200 baud）に次のように出れば成功
   ```
   起動  送信先: 温室ハウス1  間隔: 120 秒
   Wi-Fi 接続中: EHWLAN_EDU... 接続OK  IP: 10.x.x.x  電波: -55 dBm
   CO2: 412 ppm  温度: 25.0 ℃  湿度: 53.5 %
   ログイン OK
   送信結果: 200
   ```

- 書き込み後に起動しないときは **R ボタン**（USB-C 左脇）でリセット
- ポートが見えない・書き込めないときは **B ボタン**（USB-C 右脇）を押したまま USB を挿す
- シリアルに何も出ないときは「ツール」→「USB CDC On Boot」→ Enabled

## 同じハウスに2台置くとき（Pico W と ESP32 など）

ダッシュボードはハウスごとに **一番新しい1件** を表示する。同じ `LOCATION` に2台が送ると、
表示が2台の値で交互に入れ替わり、CO2 は ESP32 の値が最新のときだけ出る（それ以外は「--」）。
次のどちらかにする。

- **おすすめ**：ESP32（STCC4）をそのハウスのセンサーにして、Pico W は別のハウスに移す
  （STCC4 の温湿度は DHT22 より精度が高い）
- まだセンサーの無いハウスに ESP32 を置く

## よくあるエラー

| 表示 | 原因と対処 |
|---|---|
| `ログイン失敗 400` | `secrets.h` のセンサー用アカウントのパスワードが違う |
| `送信拒否(403)` | ルールを貼り直していない（CO2 が許可されていない）、またはハウスIDが未登録 |
| `送信結果: -1` など負の数 | Wi-Fi や校内ネットワークのフィルタリング。Pico W は送れているか確認 |
| `センサーエラーのため送信しません` | STCC4 の状態フラグにエラー（電源電圧・SHT 未接続など）。配線を確認 |

10回続けて失敗すると自動で再起動する。
